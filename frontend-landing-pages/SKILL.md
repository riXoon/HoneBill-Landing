# Frontend Landing Pages

Build landing pages in the requested stack. Inspect the target route, design system, assets, and existing dependencies before editing. Reuse components and tokens where they match the intended design. Preserve supplied copy, calls to action, routes, forms, and visual hierarchy. For a new design, use the brief to establish the page's primary action and the content that supports it.

- For a Figma source, read [Figma-to-code](references/figma-to-code.md) before implementing.
- For animation, scroll effects, or 3D, read [Motion and 3D](references/motion-and-3d.md) before choosing an approach.
- Use [Responsive delivery and verification](references/responsive-delivery.md) when implementing or verifying a page or section.

## Build the page

1. Establish the page structure and responsive composition with semantic HTML and real content. Keep the headline, navigation, and primary action usable while media and effects load.
2. Implement the critical visual assets and typography. Add animation and 3D as appropriate to the brief, with reduced-motion behavior and a usable fallback from the start.
3. Exercise the page through its normal route. Verify the layout at the reference widths and intermediate sizes, and test the affected interactions. Run the repository's relevant checks.
4. Report actual verification, significant inferred design behavior, and any checks that lacked the necessary design, browser, or device access.
